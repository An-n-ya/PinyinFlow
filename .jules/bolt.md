## 2024-05-24 - Prevent unnecessary re-renders in InputArea component
**Learning:** Found a common anti-pattern in React architecture where a parent component (`Chat.tsx`) manages high-frequency state updates (like appending messages to `messages`), passing down callbacks (`submit_pinyin`) to a stable child component (`InputArea.tsx`). Because `submit_pinyin` was not memoized, and `InputArea` was not wrapped in `React.memo`, `InputArea` was being unnecessarily re-rendered every time a new message was added to the chat history.
**Action:** When implementing input components in chat-like interfaces, always wrap the input component in `React.memo` and ensure the submit handler passed to it is memoized using `useCallback`. This prevents the complex input component from re-rendering just because the chat history updated.

## 2024-05-24 - React.memo and unused props
**Learning:** Attempting to optimize `React.memo` by commenting out unused destructured props (e.g., `onPlay` and `onStop` in `MessageBubble.tsx`) does not prevent re-renders if the parent component is still passing down new object references for those props. `React.memo` compares the incoming `props` object itself via shallow comparison, completely irrespective of what the component body destructured. Furthermore, removing props might break expected component APIs.
**Action:** Do not remove destructured props to "fix" `React.memo` triggers. Instead, ensure the parent component passes stable references (e.g., using `useCallback` for function props) so that the shallow comparison performed by `React.memo` successfully detects unchanged props.
