## 2024-05-10 - React.memo on Input Component with Frequent Sibling Updates
**Learning:** In a typical chat interface, the parent `Chat` component frequently updates its `messages` state due to events like typing, streaming text, or audio playback state changes (e.g., `tts-finished`, `audio-played`). If the `InputArea` is a sibling to the message list and accepts props from the parent, it will re-render on *every* message state update unless wrapped in `React.memo` and provided with stable prop references (using `useCallback` on handlers like `submit_pinyin` and `play`). Without this, rapid events (like audio playback callbacks) cause needless re-renders of the input area, potentially degrading typing performance.
**Action:** Always inspect the parent component's update frequency when an input component shares state with a highly dynamic list. Wrap the input component in `React.memo` and use `useCallback` for its prop functions to isolate it from sibling update storms.
